# ADR 0001：保持领域核心的平台无关性

- 状态：Accepted
- 日期：2026-08-27
- 范围：AURA 客户端、云函数、共享包与后续运营后台

## 背景

AURA 将分阶段接入 Cocos Creator、微信小游戏、CloudBase、AI 服务商与运营后台。如果领域规则直接依赖这些平台，抽牌、解读、授权、奖励和经济规则将难以在自动化测试、云函数与后续平台中复用，也会使 SDK 升级扩散到整个系统。

项目同时需要可版本化的跨边界数据，确保客户端、云端和内容版本可以独立演进。相关产品与系统约束记录在[批准规格](../superpowers/specs/2026-08-26-aura-tarot-wechat-game-design.md)和[分阶段路线图](../superpowers/plans/2026-08-26-aura-delivery-roadmap.md)中。

## 决策

依赖只能由外向内流动：

```text
Cocos / 微信 / CloudBase / AI / Web
              ↓
         应用与适配层
              ↓
  contracts / content / domain
```

- `packages/domain` 是纯 TypeScript 领域核心，不得导入 Cocos `cc`、微信或浏览器 API、CloudBase SDK、Web 框架或任何具体 AI 服务商 SDK。
- `apps/*` 负责平台生命周期、输入输出、存储、网络和 SDK 适配；平台类型、对象和异常不得穿透到领域接口。
- `packages/contracts` 定义跨应用请求、响应、事件、配置与存档的版本化 Schema。所有不可信的边界输入必须在进入领域逻辑前验证。
- `packages/content` 只承载可版本化内容数据；`packages/test-kits` 只承载固定夹具和测试辅助。共享包不得反向依赖应用。
- Cocos 场景与组件只负责呈现和编排，不承载领域规则。CloudBase 环境标识、密钥和服务端配置不得进入公开契约。
- 新平台通过新增或替换适配器接入，不通过在领域代码中增加平台条件分支接入。
- 当前 `pnpm quality` 中的 ESLint 与边界扫描是自动防线；独立审查仍需检查依赖方向、Schema 入口和平台对象泄漏。

## 后果

正面影响：

- 领域行为可以脱离 Cocos、微信和云环境进行确定性测试。
- 平台或供应商替换被限制在适配层，降低版本升级和故障回退成本。
- 客户端与云端通过显式契约协作，兼容性变化可以按版本迁移。
- 密钥和服务端标识更不容易因共享类型或日志意外进入客户端。

成本与限制：

- 每个外部 SDK 都需要一层适配代码和相应契约测试。
- 简单功能也不能直接从领域模块调用平台便捷 API。
- 跨边界变更需要同时维护 Schema、适配器、兼容测试和迁移说明。
- 静态规则不能证明所有运行时行为，仍需要集成测试、构建检查与人工审查。

## 撤销或替代条件

只有在持续的测量证据表明该边界造成不可接受的性能、包体或交付成本，且通过适配器、代码生成、缓存或模块拆分仍无法解决时，才考虑替代本决策。任何替代必须：

1. 由新的 ADR 明确受影响的边界和数据所有权；
2. 提供平台耦合收益、迁移方案、回滚方案与安全分析；
3. 保留跨边界 Schema 验证、环境隔离和密钥不进入客户端的约束；
4. 先在非生产环境完成双版本验证，并由产品所有者批准后执行。
