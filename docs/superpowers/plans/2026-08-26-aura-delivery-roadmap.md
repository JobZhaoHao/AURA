# AURA 分阶段交付路线图

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 按可运行、可测试、可回滚的阶段交付 AURA 微信小游戏，避免同时展开多个高风险子系统。

**Architecture:** 采用纯 TypeScript 领域核心，Cocos Creator、微信、CloudBase、AI 供应商和运营后台均通过适配层接入。每个阶段只在上一阶段验收通过后展开自己的代码级实施计划。

**Tech Stack:** Cocos Creator 3.8.8 稳定版、TypeScript、CloudBase、微信小游戏、Web 运营后台、自动化测试与 CI。

**Spec:** `docs/superpowers/specs/2026-08-26-aura-tarot-wechat-game-design.md`

## Global Constraints

- 首发平台为微信小游戏，竖屏单手操作。
- 领域核心不得依赖 Cocos、微信、CloudBase 或具体 AI SDK。
- 卡牌逻辑 ID、内容规则、AI、经济、资源和存档分别版本化。
- 付费内容不得改变抽牌概率或基础解读质量。
- 首个可玩版本不得接入真实支付或付费随机抽取。
- 原始问题不得进入分析事件、普通日志或默认历史。
- 用户只与 Codex 总控对话；专项 AI 的结果由总控汇总。
- 每阶段必须有自动化证据、人工验收门和独立回滚点。

## 标准阶段循环

每个阶段严格执行同一循环：

1. 总控从已批准规格提取该阶段验收条件。
2. 总控编写该阶段代码级计划，冻结接口和文件边界。
3. 实现者先写失败测试，再提交最小实现。
4. 独立审查者检查规格符合性、代码质量、安全和测试证据。
5. 总控运行完整回归并整理可视化或真机验收材料。
6. 产品所有者只在当前主任务中批准、退回或调整优先级。
7. 通过后打阶段标签并进入下一阶段；未通过只修当前阶段。

## Token 与上下文控制

- 只在阶段即将开始时编写该阶段的详细计划，避免未验证假设造成返工。
- 每个实现任务只加载规格、当前阶段计划和直接相关文件。
- 专项 AI 返回变更摘要、测试证据和风险，不回传冗长思考过程。
- 同一模块同时只允许一个实现者修改；审查角色只读并给出问题清单。
- 状态汇报固定为：已完成、正在做、阻塞、下一验收点。

## 决策与变更控制

- 产品规则变化先修改规格并记录架构决策，再修改阶段计划和代码。
- 已验收阶段如需破坏性修改，单独创建迁移任务，不把迁移夹带到新功能。
- 价格、概率、保底、生产发布和真实资产发放始终保留人工审批。
- 本路线图只决定顺序；各阶段计划负责具体文件、接口、测试命令和提交边界。
