# AURA Milestone 1 核心玩法纵切设计

- 日期：2026-08-28
- 状态：产品所有者已批准
- 基线：`milestone-0-foundation`（托管验收提交 `346186b`）
- 首发平台：微信小游戏，`750 × 1334` 竖屏单手操作
- 前置规格：[AURA 产品与系统设计规格](2026-08-26-aura-tarot-wechat-game-design.md)
- 架构约束：[ADR 0001：保持领域核心的平台无关性](../../decisions/0001-architecture-boundaries.md)

## 1. 阶段目标

Milestone 1 的唯一目标是证明离线塔罗玩法本身成立：抽牌结果可信且可复现，规则版解读可以独立完成一次体验，非卡牌 UI 有稳定的视觉层级，本地记录可用，并能在 Cocos Creator 与微信小游戏真机环境中完成流程。

本阶段最终范围包含：

- 78 张标准塔罗牌的稳定逻辑身份与初始牌义数据。
- 每日一牌、单张问答和固定“过去—现在—趋势”三牌阵。
- 固定种子、正逆位、不重复抽牌和规则版解读。
- 默认月光疗愈主题下的洗牌、抽取、翻牌与结果阅读体验。
- 本地图鉴、本地历史和结果卡本地预览。
- 表现资源可替换边界、缺失回退和低特效降级。

交付采用“单卡纵切优先”：先把单张问答做成完整、可测试、可真机验收的闭环，再复用同一核心扩展每日一牌和三牌阵。

## 2. 范围外

Milestone 1 不实现：

- CloudBase 权威抽牌、微信身份、跨设备同步或云端历史。
- AI 表达增强、真实 AI 调用或 AI 供应商适配。
- 真实 VIP、会员、支付、订单、商品、商城或权益服务。
- 主题包和牌组包下载、签名、热更新、运营分发或版本迁移。
- 真实分享；结果卡只做本地预览。
- 经济、奖励、CDK、随机商品、运营后台或公开发布。
- 卡牌正面插画与卡背的美术设计。相关正式素材由产品所有者后续提供。

## 3. 已批准的产品决策

### 3.1 首个可玩闭环

首个完成的可玩闭环是单张问答：

`选择类别 → 可选问题 → 静心 → 抽牌 → 翻牌 → 规则解读 → 可选保存/结果卡预览`

问题类别固定为：

- 综合（默认）
- 感情与关系
- 事业与学业
- 自我成长

问题文本可输入、也可跳过。产品不提供医疗、法律或投资类别；遇到高风险表达时显示安全说明，不给出确定性专业结论。

### 3.2 基础与 VIP 深度解读

所有玩家获得完整、专业且不被刻意削弱的基础解读，包括：

- 正位与逆位核心含义。
- 当前问题类别下的核心解释。
- 一句话结论。
- 可执行建议。
- 必要的安全边界。

VIP 深度层可以增加类别细节、关系分析、推理过程、替代视角和反思练习，但不得改变抽牌结果、概率、核心结论或安全边界。

Milestone 1 只显示一个可见但锁定的 VIP 深度模块，并提供本地测试开关切换普通态与 VIP 态。模块不显示价格、购买入口或真实权益状态。

### 3.3 历史、图鉴与结果卡

- 历史完全由用户手动保存；未保存的测算不会进入历史。
- 原始问题默认只用于当次测算，遵守主规格的隐私规则。
- 卡牌一旦揭示即自动点亮图鉴，与是否保存历史无关。
- 图鉴按稳定逻辑卡 ID 累计，不因更换牌组重复计数。
- 结果卡只做本地预览，不接真实分享。

结果卡始终包含：AURA 标识、模式、卡牌、牌名和正逆位。用户可以选择是否包含日期、问题类别、核心结论和建议。原始问题默认关闭；用户启用时必须看到隐私提示。结果卡不得包含完整长解读、VIP 深度内容、内部规则或调试数据。

在产品所有者尚未提供正式牌面时，Milestone 1 的结果卡和图鉴允许使用中性卡牌容器、牌名与正逆位标签作为合法占位，不得因此临时创作或绑定正式牌面美术。

## 4. 架构与依赖方向

依赖继续遵循 ADR 0001：

```text
Cocos Creator / 微信本地能力
              ↓
       应用编排与适配器
              ↓
contracts / content / domain
```

### 4.1 `packages/contracts`

定义跨层稳定 Schema，至少覆盖：

- `CardId`
- `Orientation`
- `ReadingMode`
- `QuestionCategory`
- `SpreadPosition`
- `ReadingSession`
- `ReadingResult`
- `SafetyDisposition`
- `DiscoveryRecord`
- `LocalHistoryEntry`
- `DeckManifestRef`
- `ThemeManifestRef`
- `AnimationManifestRef`

契约可以认识稳定资源标识，但不得包含 Cocos 对象、具体资源路径、动画实例或平台异常。

### 4.2 `packages/domain`

纯 TypeScript 领域核心负责：

- 固定种子洗牌与抽取。
- 单张和三张不重复抽取。
- 正逆位生成与关闭逆位设置。
- 每日一牌的本地稳定日种子实验规则。
- 规则版解读拼装。
- 图鉴发现累计与历史追加。

`themeId`、`deckId` 和 `animationId` 不得参与种子、抽牌、正逆位或解读计算。

Milestone 1 的每日一牌使用首次本地启动生成的 `installationId`、设备本地自然日 `YYYY-MM-DD`、模式和 `rulesVersion` 派生种子。首次生成后必须按自然日和规则版本缓存逻辑结果，同日重复进入直接返回缓存；主题、牌组、逆位偏好等后续变化不能改写当日结果。清除本地数据、重装或修改设备日期可能改变结果，这是离线实验版的已知限制；Milestone 2 再由服务端权威会话替代。

### 4.3 `packages/content`

承载两类版本化数据：

1. 78 张牌义、牌阵位置和解释规则等逻辑内容。
2. 牌组、主题和动画的声明式表现清单。

表现清单只能映射资源和视觉参数，不得定义概率、牌义、抽牌状态分支或历史规则。

### 4.4 `apps/game-client`

Cocos 客户端负责：

- 页面与状态编排。
- 输入、触控、动画播放和资源加载。
- 本地存储适配。
- 资源缺失回退与低性能降级。
- 将已确定的领域结果呈现给玩家。

动画只展示已经确定的结果，不能在动画回调中重新决定抽牌。

## 5. 数据与规则不变量

- 78 张逻辑卡牌 ID 全局唯一且永久稳定，例如 `major.fool`。
- 同一输入种子、问题类别、安全分流结果与同一规则版本产生相同的牌、正逆位、牌阵位置和规则解读。
- 单张问答只返回一张合法卡牌。
- 三牌阵返回三张不同的逻辑卡牌。
- 关闭逆位后，任何牌组或动画都不能产生逆位结果。
- 牌义由 `cardId + orientation + questionCategory + spreadPosition + rulesVersion` 决定，不绑定具体美术。安全层使用边界校验得到的稳定 `safetyDisposition`（至少为 `standard` 或 `high-risk`）决定是否追加安全响应；不把原始问题写入普通历史或日志。
- 更换主题、牌面、卡背、封套或动画不能改变抽牌、解读、图鉴或历史语义。
- 历史保存逻辑事实与可选表现引用；旧资源缺失时仍能使用默认皮肤还原相同结果。

每张卡的初始逻辑内容至少包含：阿卡纳、花色或序号、中文名称、正逆位关键词、正逆位核心含义、四类问题解释、行动建议及必要安全提示。

## 6. 单张问答交互流程

### 6.1 进入与提问

用户选择“单张问答”，看到四类问题类别和可选问题输入。默认类别为“综合”。输入区明确显示可以跳过，不制造必须透露隐私才能抽牌的压力。

### 6.2 静心、抽取与揭示

静心页只提供一个主要动作。抽卡舞台可以使用替换后的卡牌封套、背景和效果，但主操作始终清晰。

领域层先生成并保存本次内存结果；表现层随后播放洗牌、抽取和翻牌。揭示时卡牌成为第一视觉焦点。正逆位同时通过牌面方向和克制的“正位／逆位”文字标签表达。

### 6.3 卡牌主导结果页

- 首屏第一焦点是大卡面容器。
- 大卡面容器目标高度为首屏可用高度的约 35% 至 42%；具体值可按安全区微调，但不同主题不得改变其宽高比和正文起始位置。
- 一句话核心结论紧随卡牌，并在不滚动时可见。
- 完整解读开头露出一至两行，配合轻微渐隐提示继续下滑。
- 详细解释、建议、VIP 模块和操作进入第二阅读层。
- 翻牌高光完成后迅速收束；阅读期间背景和装饰接近静止。
- halo 和外圈高光只能在卡牌容器安全区外扩，不得侵入核心结论或正文区域；替换素材采用完整显示优先的等比适配，不得拉伸，必要裁切只能发生在预先定义的非关键信息安全区。

### 6.4 完成操作

揭示后自动点亮图鉴。保存历史、打开结果卡预览、重新开始和返回入口具有明确主次关系。保存成功采用轻量反馈，不伪装成云端同步。

## 7. 非卡牌 UI 视觉章程

视觉命题为“被月光托起的可信仪式感”。主基线是：

- 80% 疗愈月仪：安静的深夜紫蓝、月白、雾紫和柔光。
- 15% 古典秩序：细铭刻线、克制边框和标题秩序。
- 5% 星光高光：仅用于翻牌完成等瞬时反馈。

建议基础色彩 Token：

- 深夜背景：`#100C19`
- 雾紫：`#8C789D`
- 月白：`#F1ECF5`
- 正文浅灰紫：`#CEC4D6`
- 克制旧金：`#B6A06D`

签名元素包括十二阶段月相环、对称且可解释的神圣几何、卡牌背后的柔和月晕和细铭刻分隔线。不得使用无来源咒文、随机拼接的宗教符号或持续抢焦点的星云效果。

### 7.1 字体系统

- 中文短标题：思源宋体 SC SemiBold。
- 英文标题、罗马数字和章节编号：Cinzel。
- 正文、按钮和工具信息：思源黑体 SC 或等价轻量中文黑体。

罗马碑铭感只进入短标题、英文与数字层。正文优先保证微信小屏可读性。中文标题字体应按批准文案做字符子集并保留许可证文件；加载失败时回退到系统字体，不得出现空白文字。

### 7.2 布局与无障碍

- 基准设计分辨率为 `750 × 1334`。
- 主要触控区域不小于 `88 × 88` 设计像素。
- 主操作尽量位于下半屏单手舒适区。
- 长文必须置于稳定底板上，不直接压在复杂法阵或动态背景上。
- 正文对比度、字号和行高优先于氛围。
- 动效需要支持减少动画与低特效降级。

### 7.3 视觉审查硬门

- 卡牌始终是最高对比、最高细节和第一视觉焦点。
- 背景线条不得比卡牌容器边界更亮。
- 常驻动效慢且弱，关键反馈短且明确；阅读时基本静止。
- UI 实现者不能自行批准自己的视觉结果，由视觉总监独立审查。

## 8. 可替换表现资源合同

卡牌正面、卡背、封套、抽卡舞台、抽卡效果、抽卡背景和背景动画都必须能够在后期替换，不能写死在场景或玩法逻辑中。

### 8.1 固定层

主题不得修改：

- 信息架构与页面顺序。
- 卡牌容器比例、安全区和最大占屏比。
- 结果页内容顺序。
- 主次按钮关系与触控区域。
- 标题、正文和工具信息的字体角色。
- 加载、禁用、失败和保存反馈的位置。
- 可读性、动效上限与低性能降级规则。

### 8.2 可替换槽位

- `BG_BASE`：全局底色、渐变或轻纹理。
- `BG_PATTERN`：低对比几何或法阵层。
- `BG_ORBIT`：月相环和外围装饰层。
- `STAGE_FRAME`：抽卡与翻牌舞台。
- `CARD_CONTAINER_CHROME`：不属于牌面的 halo、底托和阴影。
- `PANEL_SURFACE`：问题、解读和弹层底板。
- `BUTTON_SKIN`：按钮表皮与按下反馈。
- `ICON_ACCENT`：图标和状态装饰。
- `TRANSITION_FX`：通用页面与翻牌后转场。

任何槽位缺失都必须按预先声明的策略隐藏或回退，不得白屏、错层或阻断抽牌。

回退分类固定为：

- 可直接隐藏：`BG_PATTERN`、`BG_ORBIT`、`ICON_ACCENT` 和非关键粒子。
- 必须回退到默认月光主题：`BG_BASE`、`STAGE_FRAME`、`PANEL_SURFACE` 和 `BUTTON_SKIN`。
- 必须使用中性保底：`CARD_CONTAINER_CHROME` 和 `TRANSITION_FX`，分别回退为基础阴影/描边与淡入淡出。
- 卡牌正面、卡背或封套缺失：使用中性卡牌占位容器和文字标识，不能阻断逻辑结果展示。

### 8.3 M1 与后续边界

Milestone 1 只证明：

- 默认主题通过统一清单加载。
- 一套极简替代样例可以替换背景、容器和基础效果。
- 替换前后布局、触控、抽牌和解读不变。
- 缺失资源有硬回退。
- 低特效模式可以关闭背景动画、粒子、多层视差和强发光。

完整主题包系统、运行时下载、签名校验、热更新、商城授权、页面级主题差分和音画联动延后到后续里程碑。

## 9. 本地数据与隐私

- 未保存的测算不会进入历史。
- 原始问题默认只用于当前测算，不进入分析事件、普通日志或结果卡。
- 用户主动保存历史时，遵守主规格的私有数据规则。
- 历史至少保存会话 ID、模式、问题类别、稳定安全分流结果、规则版本、卡牌 ID、正逆位、位置、结果文本版本、创建时间和可选主题/牌组引用。
- 图鉴发现记录只按逻辑卡 ID 追加。
- 本地数据损坏时跳过或隔离异常记录，显示可理解提示，不阻止客户端启动。

## 10. 测试先行与验收

### 10.1 自动化测试

- 78 张 ID 唯一且内容必填字段完整。
- 任一牌组清单对 78 张 ID 一一覆盖，无缺失、重复或多余映射。
- 固定种子可复现单张、三张、正逆位和规则解读。
- 同一问题类别和安全分流结果可以重放相同规则解读；历史 Schema 完整保留重放所需的非敏感逻辑字段。
- 每日一牌在同一本地安装、自然日和规则版本内返回缓存的相同逻辑结果；主题、牌组和表现设置不改变结果。
- 三牌阵不重复；逆位关闭时不产生逆位。
- 更换 deck/theme/animation 前后逻辑结果完全一致。
- 动画或非关键资源缺失时回退成功，结果仍可显示和保存。
- 未保存会话不写入历史；揭示卡牌自动点亮图鉴。
- 切换牌组不会重复累计图鉴。
- VIP 本地开关只改变静态深度模块可见性，不引入权益、价格、支付、云端状态或第二套抽牌流程。
- 结果卡默认不包含原始问题、完整长解读或 VIP 深度内容。

### 10.2 客户端与真机验证

- Cocos Creator 3.8.8 竖屏预览通过。
- 微信小游戏开发构建通过。
- 默认主题与极简替代样例各完成一次单卡完整流程。
- 常见真机完成触控、抽牌、翻牌、下滑阅读、保存和结果卡预览。
- 低特效模式关闭高成本表现后流程仍完整。
- 产品所有者验收抽卡手感与视觉层级。

### 10.3 独立审查

- 项目管控角色检查范围、测试证据、风险和退出条件。
- 领域审查角色检查逻辑与表现解耦、确定性和数据不变量。
- 视觉总监检查卡牌焦点、跨页面一致性、字体、动效收束和无障碍。
- 同一模块同时只有一个实现者修改；实现者不能批准自己的工作。

## 11. 建议交付顺序

1. 契约、78 张稳定 ID、最小内容数据和可替换资源合同。
2. 固定种子、单卡抽取、正逆位与基础解读测试。
3. 默认主题骨架、统一资源槽位和中性占位/回退能力。
4. 单张问答 Cocos 流程。
5. 本地图鉴、手动历史、结果卡预览和极简替代样例验证。
6. 单卡真机验收。
7. 在核心玩法通过后加入限时的本地 VIP 静态展示分支。
8. 复用核心扩展每日一牌。
9. 复用核心扩展固定三牌阵与组合解读。
10. Milestone 1 全量回归、独立审查和产品验收。

单卡真机验收只是中途检查点，不是 Milestone 1 的退出门。

## 12. Milestone 1 唯一退出门

Milestone 1 只有在以下条件全部满足后才能封版、打标签并进入 Milestone 2：

- 78 张 Schema 与初始内容通过完整性检查。
- 单张问答、每日一牌和固定三牌阵全部完成自动化与真机流程。
- 固定种子、正逆位、三牌不重复和规则解读测试通过。
- 默认主题与极简替代样例均完成完整流程，资源缺失和低特效降级通过。
- 本地图鉴、手动历史和结果卡本地预览通过隐私与恢复测试。
- 仓库质量门与托管 CI 通过固定 Node/pnpm 版本。
- 领域、视觉和项目管控独立审查无阻断问题。
- 产品所有者在真机批准抽卡手感、卡牌焦点、阅读层级和整体视觉一致性。
- 形成单独可回滚提交边界；未授权不得推送标签或开始 Milestone 2。

任何单一子流程或中途真机检查通过，都不得被视为 Milestone 1 完成。

## 13. 延后决定

以下事项不阻塞实施计划，但在相应阶段开始前必须由产品所有者单独批准：

- 正式卡牌正面、卡背和封套素材及其许可证明。
- 完整主题包和牌组包的分发、授权与版本迁移。
- 真实 VIP 定价、会员权益、支付和云端鉴权。
- AI 深度解读的模型、提示词、安全评测和费用策略。
- 真实结果卡分享与微信隐私设置。

## 14. 与上位规格的关系

本设计细化并覆盖主规格的 Milestone 1 口径。若两者存在差异，以本设计中产品所有者于 2026-08-28 批准的以下决策为准：

- 基础解读完整，VIP 可以提供额外深度，但不能改变抽牌、核心结论或安全边界。
- 历史由用户手动保存；图鉴在揭示时自动点亮。
- 结果卡在 Milestone 1 仅做本地预览。
- 牌面与卡背美术暂不设计；表现层必须预留后期可替换接口。
